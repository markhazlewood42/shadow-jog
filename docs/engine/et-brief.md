# ET Editor port: build brief

Source: [migration.md](migration.md) "Editors and tools" track 1, principle 11 (the editor contract), principle 12 (GPU timing), "M8 Remove legacy", [et-survey.md](et-survey.md) (all facts below come from it), [m6-brief.md](m6-brief.md) (format), `docs/TOOLING-UI.md`, and the lean loop in `CLAUDE.md`. Branch: `engine-et-editor-port` (from `main` after M7). **Nothing is built until Mark approves this brief.** Task 1 re-checks every survey fact.

## 1. Goal

- Every existing tool except the trailer opens, edits, saves and previews on the new engine, and no tool file reaches `engine/game`, `display`, `postfx` or `moments`, or `LegacyScene` or `LegacyShape`. The 14 tools are in the survey, section 2. 13 are ported or kept (11 that exist, 2 built). 1 is deleted: the trailer tooling (T7), decision 3. [#84](https://github.com/markhazlewood42/shadow-jog/issues/84) tracks its re-creation on the new engine.
- The Battle Stage Editor and Battle Test exist on the new engine. They are built from the archive tag `archive/phaser-stage-2026-10-09`, because M3 did not port them.
- Every tool has a test that opens it. 6 of the 12 tools that exist have none today.
- Not in ET: new tool features (`TOOLING-UI.md` 4.5 stays later), the Editor suite, the 27 game files that still import the old engine (M8, or M4), the trailer re-creation (#84, after ET), `src/engine` deletion (M8), the real hacking scene, frame-by-frame moves (`TOOLING-UI.md` 6.2).
- Exit check (migration.md): every existing tool opens, edits, saves and previews on the new engine, and the old-engine tool code is gone before M8.

## 2. Survey facts that change the plan

- **Two of the 14 tools do not exist on this branch.** The Battle Stage Editor is 16 files and 5,541 lines on the archive tag, plus a 378-line page. The migration text says "with M3". `m3-brief.md:21` moved it to ET. ET builds it.
- **5 tools depend on the old engine:** the art viewers (5 scenes) and the trailer (direct, `extends Scene`), the field show hooks and the dev routes file (direct, type imports), and the FX lab (indirect, through `scenes/battlekit/gpufx.ts:43`, plus `LegacyShape`). ET ports 4 of them and deletes the trailer (decision 3, #84). 7 are clean: the DEV menu, the animation editor, art review, art swap, the stage lab, the engine lab and the 3D entry.
- **The boundary with M8 is 8 of 35 files.** 35 files outside `src/engine` import the old engine. 8 are tool files (ET): 7 are ported (the 5 viewer scenes, `fieldshow.ts`, `devroutes.ts`) and 1 is deleted (`trailer.ts`, decision 3). 27 are game code (M8): 15 scenes, 5 battle or field kit files, 7 boot and glue files. The FX lab is not one of the 8: `fxlab.ts` imports none of `engine/game`, `display` or `postfx`. Its `Game` and `LegacyShape` types come from `src/sje/runtime` (`fxlab.ts:30-31`). It reaches `postfx` and `moments` through `gpufx.ts`, which is game code. `LegacyShape` goes when the lab becomes a `Scene`.
- **The shipped stage leaves out the spike's move animations** (`src/battlestage/live.ts:19`). The spike's Battle Test plays them from `moves.json` (only on the archive). That is decision 2.
- **Two stage data sets exist.** The game reads the 640 set (`stages-640.json`, `hud-640.json`). The archive editor writes the 480 set. That is decision 4.
- **Five tools have no browser test.** The DEV menu cannot be mounted under Playwright (`devmenu.ts:39`). The animation editor and the art review have write endpoints with no dry run.
- **The shipped bundle holds no tool code**, and has 0.3 kB (total) and 0.5 kB (first play) of room. ET touches one shipped game file at most (`gpufx.ts`).
- **Principle 12 (GPU timing) does not apply**, unless the diff touches `src/sje/render/`, `src/sje/display/` or `src/sje/three/`. No planned task does. Pass line 11 checks it. The engine has no `Zone` or `pick`; if the editor needs one, task 1 says where it goes, and a change in `src/sje/display/` would trigger one `npm run perf`.
- **Contradiction:** migration.md M8 deletes four paths; its file table deletes `src/engine/*`. ET does not depend on which is right. M8's brief must pick.

## 3. Decisions for Mark (recommendation first). Answered 2026-10-13: 1 engine-free, 2 B, 3 all but the trailer (delete it, #84), 4 the 640 set, 5 separate

1. **How far each tool is ported.** **Decided 2026-10-13 (Mark): engine-free, the recommendation.** Recommend: engine-free, no new features. Every tool file imports none of the old engine. The FX lab becomes a real new-engine `Scene`. `gpuSpell` and `gpuCast` take the effects object as an argument: the game passes `postfx`, the lab passes `game.fx`. The lab also calls `game.fx.loadData` after each edit (survey section 7). The 5 viewers move to a new-engine scene base. All tool code lives in `src/dev`. Alternative: keep `LegacyShape` for the FX lab, the viewers and the trailer until M8. That is less change now, but the exit check is not met and M8 must convert 6 scenes.
2. **Battle Test depth.** **Decided 2026-10-13 (Mark): option B, the recommendation. The stop-and-ask rule stays.** Option A: port the spike's Battle Test whole: `battleflow`, `perform`, `moves`, `strike`, `controls`, `kneel`, `stills`, `fx` and `moves.json` (about 2,000 lines plus 21 kB of data; E24 asks whether `moves.json` is your data, safe default yes). Option B (recommended): the dialog and options port with the editor. The fight runs on the game's own `BattleScene` over the live stage, with the page's unsaved stage swapped in through `loadStage`. It plays what the game plays, with no move animations, as the shipped stage does. A would add a second performer that the game never uses. Task 1 checks that the editor page can run `BattleScene` over its stage. **If it cannot, the builder stops and reports. It does not fall back to A without Mark.** Task 1 showed that it can (2026-10-13). Pass line 2 got a narrow exemption for this (Mark, 2026-10-13).
3. **Tools nobody uses.** **Decided 2026-10-13 (Mark): port all except the trailer tooling (T7). Mark: "Delete it but make sure we're tracking to re-create it later."** ET deletes the trailer and does not port it. [#84](https://github.com/markhazlewood42/shadow-jog/issues/84) tracks the re-creation on the new engine, after ET. The delete list is in task 3. The other 13 tools are ported or kept. The viewers are 215 lines. The trailer was 202 lines, and `scripts/trailer.mjs` re-shot it after any art change. Art swap is the in-game try of the art review.
4. **Which stage files the editor writes.** **Decided 2026-10-13 (Mark): the 640 set only, the recommendation.** Recommend: the 640 set only (`stages-640.json`, `hud-640.json`, plus the shared `axes.json`, `enemyfacing.json`, `heroes.json`). The 480 set stays frozen for the parity fixtures. Alternative: both, with a switch. That doubles the save path.
5. **Merge ET into M8.** **Decided 2026-10-13 (Mark): no, they stay separate, the recommendation.** Recommend no. ET ends when 7 tool files are ported, the trailer is deleted and 2 new tools are on the new engine. M8 is the deletion of `src/engine` and the conversion of 27 game files, with M4 optional. One PR for both would hide the editor review in a deletion PR.

## 6. Editor contract (principle 11)

(a) Each tool keeps its data file as the only source: `fx.json`, the stage set, `skeleton.json`, `review.json`. (b) Each save goes through the checker the game loads the file with (`checkFx`, `prepareSave` over `loadStages` and its siblings, `rig2/check`). (c) Hot reload: the FX lab calls `game.fx.loadData` (pass line 14); the stage editor calls `BattleStageScene.loadStage` (`stagescene.ts:407`); the animation editor and the art review do not hot-reload into a running game (the game reads their files at startup). **Gap named:** closes with the Animation Composer in the Editor suite. (d) The stage editor uses `snapshot` and `restore` (`stagescene.ts:417`, `:436`). (e) Battle Test uses the driver's `step(n)` (`battledrive.ts:364`). Changed in task 6: `BattleTest.advance(n)` yields between ticks because `BattleScene` rounds are promise chains; `battleTrace` stays the reference (survey section 10). What stays in code: panel layouts and shortcut tables. No Pixi object leaves `src/sje`. **Gaps in the FX lab:** (a) editing `FxParams` and (d)/(e) scrubbing do not exist in the lab. They are new features, so they go to the Editor suite (survey section 7). **Control:** pass lines 6, 9 and 14.
