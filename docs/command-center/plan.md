# Shadow Jog Command Center — Implementation plan

> For agentic workers: use superpowers:subagent-driven-development; steps use - [ ] checkboxes.

- **Goal:** Build one local website that shows what is going on now, lets Mark read every Shadow Jog doc, and lets him answer design decisions.
- **Architecture:** One Node server has a module for each source: docs, engine review, status, git, GitHub, Claude sessions and decisions (GitHub issues). Each module serves a read-only JSON `Panel<T>` and sends change events over server-sent events. One route writes: Mark's answer to a decision issue. A React page app shows the Now page, the docs site, the Agents page and the decision pages.
- **Tech stack** (versions checked with `npm view` on 2026-10-05, pinned exactly). Server: `hono` 4.13.13, `@hono/node-server` 2.1.3, `chokidar` 5.0.0, `markdown-it` 15.0.2, `github-slugger` 2.0.0, `yaml` 2.9.1, `minisearch` 7.2.0, `open` 11.0.4, `tsx` 4.23.15. Page: `react` and `react-dom` 19.3.0, `react-router` 8.4.0, `vite` 8.3.2, `@vitejs/plugin-react` 6.1.2, `tailwindcss` and `@tailwindcss/vite` 4.3.3, `@heroui/react` and `@heroui/styles` 3.2.6, `lucide-react` 1.52.0, `@cruxgarden/plasma-ui` 0.7.0, `@fontsource-variable/geist` and `@fontsource-variable/geist-mono` 5.3.0 (fonts load from packages, so the site works offline). Tests: `typescript` 7.0.2, `vitest` 5.0.3, `@playwright/test` 1.63.0, and the `@types/*` packages. Why `markdown-it`: its token list gives the HTML, headings, links and search text in one parse. Why `hono`: a test calls a route with `app.request()` and no open port.
- **Spec:** [design.md](design.md), approved by Mark on 2026-10-05 with the decision inbox (section 5.5) and the look (section 4.2). Read it first. Each builder gets its task block, the global constraints, and the review focus lines for its task.

## Global constraints

- **Address:** the server listens on `127.0.0.1` only, on `config.port` (3009, and 3010 for the E2E server). It answers 403 to any `Host` header except `localhost:<port>` and `127.0.0.1:<port>` (this blocks DNS rebinding). If the port is busy, print one line and exit. Never kill a process.
- **One write route:** the server is read-only except `POST /api/decisions/<n>/answer`. Through `gh` it posts one comment, swaps the label `decision` for `decided` and closes the issue. It writes no repo file and runs no git operation. Any other method gives 405. The `Runner` has an exact list of read commands and these three write shapes, and it pins `--repo` to `githubRepo`. The write route accepts only a same-origin JSON request that carries a token the server makes at each start. The token sits in the page, so doc text must never run script.
- **Allow-list:** the shadow-jog repo, the `shadow-jog-phaser` checkout, the session folders under `~/.claude/projects/` that the config names one by one, with no name-prefix match (the `shadow-jog` and `shadow-jog-phaser` folders, and the home-base folder, see Open points), and the issues of `markhazlewood42/shadow-jog` through `gh`. Docs and files go out by an id from the index. No route takes a path.
- **Trust:** the repo is public. Only issues, comments and labels by `markhazlewood42` count. Issue text shows as plain text, never as HTML.
- **Place:** `tools/command-center/` has its own `package.json`, lock file and `node_modules`, and imports nothing from `src/`. The game does not change: no new dependency, no bundle or CI change. The only root code or config edit is one `cc` script in `package.json`. The other root changes are text: docs, `CLAUDE.md` and the issue template. `npm run check` at the root must still pass.
- **Start:** `npm run cc` at the repo root installs the tool's packages, builds the page app, starts the server and opens a tab. It must work on Node 24 on Windows in Git Bash, so Node code never spawns a `.cmd` shim.
- **Look:** one token set in `src/web/tokens.css`, copied from the diagram profile `docs/diagrams/profile/shadow-jog.md` (color mapping and contrast in `NOTES.md`): navy panels (`paper`, `paper-2`), lavender frame (`rule-solid`), white text (`ink`). Amber (`accent`) marks one or two focal items per page. Cyan (`link`) is for links only. No glow, no shadow. Geist and Geist Mono. The ratios in `NOTES.md` are the floor for all text. The HeroUI theme and the PlasmaUI mood both read the tokens. No color value exists outside `tokens.css`.
- **Style:** Tailwind v4. No `* { margin: 0 }` reset and no `font-family` on `body`. Icons come from Lucide React only, never inline SVG.
- **HeroUI v3 is a beta** (Mark's rule, although npm `latest` is 3.2.6). Before the first use of a component, call the HeroUI MCP `get_component_docs` and read the `.d.ts` files in `node_modules`. Never guess an API. Check other libraries with Context7.
- **Errors:** every async panel has its own error state and shows when it last updated. It never fails silently. One broken source never blanks a page.
- **Tests and code:** Vitest for units. Playwright for E2E, on its own server at port 3010 that never reuses a running one. Strict TypeScript. Comment the code for a reader who is new to Node and React: explain why, not what.
- **Temp files and fixtures:** screenshots and scratch files go to the scratchpad or the OS temp folder, never into the repo. Delete screenshots when the task ends. The repo is public, so fixtures are synthetic: never copy real session text, names or secrets.
- **Git:** work on branch `command-center`. Commit and push after each task. No `Co-Authored-By` lines. Never commit to `main`. Open one PR at the end.

## Review focus

- **A doc with no frontmatter** (about 20 of 45 docs today, for example `docs/PHASE-0.2.md`): the title is the first `#` heading, type and status show empty, the date comes from git. Tests: Task 2 (title), Task 3 (date).
- **Two "Next up for Mark" lists in `status.md`** (the current one and an older one under "history"): use only the first list inside the current "Right now" section. A wrapped item stays one item. Test: Task 6.
- **Sessions that Mark starts in `home-base` but that work on Shadow Jog** (their files and workflow journals sit in the home-base folder): the `cwd` of a session is the `cwd` of its newest line that has a `cwd` field. Only `user`, `assistant`, `attachment` and `system` lines carry one, and an idle session ends in metadata lines such as `last-prompt`, `cost-state` and `mode`. Keep a home-base session only when that `cwd` is inside an allow-listed root, and drop any session whose `cwd` is outside every root, compared by path segments. Read a Your move box only from a reply whose own `cwd` is inside a root. Other sessions never appear in any response. Test: Task 7.
- **A session file with a half-written last line, one very long line, an unknown line type, or 300 MB of size:** read only a bounded end of the file, use the last complete line, show "unknown", never throw. Test: Task 7.
- **The decision table changes shape when the engine docs are edited** (the same file also holds a second table with `E` rows): find columns by header name, ignore other tables, show a visible error when a column is missing. Test: Task 5.
